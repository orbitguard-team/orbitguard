# Сценарии OrbitGuard — OG-06 (#6)

Три воспроизводимых сценария для демонстрации и тестов. Каждый загружается
из JSON без ручного ввода: `orbitguard.scenarios.load_scenario(path)`.
Все данные **синтетические**. Параметры подобраны по открытым источникам
(таблица в конце), а ожидаемый статус каждого сценария обоснован расчётом,
а не заглушкой.

| Файл | Ожидаемый статус | Что показывает |
|---|---|---|
| `scenarios/safe_flyby.json` | `already_safe` | Сближение на 4 км: манёвр не нужен |
| `scenarios/dangerous_feasible.json` | `feasible` | Сближение на 120 м через 3 ч; уходит манёвром 5–10 см/с |
| `scenarios/late_warning_no_solution.json` | `no_feasible_candidate` | То же сближение, но предупреждение за 15 мин: в пределах манёвра решения нет |

## Общие параметры

| Параметр | Значение | Откуда |
|---|---|---|
| Спутник | 6U CubeSat: 10 кг, средняя площадь сечения 0.071 м², Cd = 2.2 | Габариты 6U 10×22.6×36.6 см; средняя площадь хаотично ориентированного выпуклого тела — S_полн/4; масса — допущение (типично 8–12 кг) |
| Орбита спутника | Перигей 415 км, апогей 425 км, i = 51.64°, e ≈ 0.00074 | МКС-подобная орбита: так выводятся CubeSat с МКС |
| Фрагмент | i = 82.6°, перигей ≈ 405 км, апогей ≈ 470 км, 0.4 кг, 0.03 м² (0.075 м²/кг), Cd = 2.2 | Наклонение облака Kosmos 1408; от его фрагментов МКС уклонялась в 2022 г.; отношение площади к массе — типичное по LeoLabs |
| Порог | `safe_distance_m` = 1000 м, запас `distance_margin_m` = 1 м | Учебный детерминированный порог (см. «Ограничения») |
| Силы | Только центральное поле; J2, атмосфера, Луна, Солнце выключены | Контракт v0.1: другие силы ещё не реализованы |
| Численные параметры | По умолчанию из контракта: rtol 1e-10, шаг ≤ 10 с, допуск по времени 1 мс | `models.Numerics()` |
| Предел манёвра | `dv_max_mps` = 0.5 м/с за один импульс | Допущение для малой ДУ: 0.5 м/с при тяге 40 мН и массе 10 кг набирается за ~125 с ≪ периода 5578 с, поэтому импульсное приближение допустимо |

Высота отсчитывается от сферы R = 6378.137 км, как в контракте. Над эллипсоидом
на широте 40° она примерно на 9 км больше.

## Как построены сценарии

Генератор — `tools/build_scenarios.py`, аналитический эталон —
`tools/twobody_reference.py`. Алгоритм:

1. Элементы орбиты спутника задаются в момент главного сближения (TCA).
   Аргумент широты u = 55°: восходящий участок, широта ≈ 40° с.ш.
2. Плоскость орбиты фрагмента проводится через точку спутника с наклонением
   82.6°. Истинная аномалия подбирается так, чтобы радиусы совпали.
   Фрагмент движется навстречу, на юг, поэтому угол между скоростями
   ≈ 116° и относительная скорость 13.0 км/с.
3. Фрагмент сдвигается на вектор промаха, перпендикулярный относительной
   скорости. Поэтому в TCA r_rel·v_rel = 0 точно: момент сближения задан
   конструкцией, а не подобран.
4. Оба состояния переносятся на эпоху сценария аналитически: задача двух
   тел, универсальная переменная Кеплера (Curtis, алг. 3.3–3.4; Vallado,
   алг. 8). μ и R берутся из `orbitguard.constants` — те же, что в расчёте.
   Интегратор OG-02 здесь не используется, поэтому совпадение с ним — независимая проверка.
5. На всём горизонте ищутся все минимумы дистанции: корни r_rel·v_rel = 0
   с шагом поиска 2 с, уточнение методом Брента до 1e-9 с, плюс границы.
   Генератор проверяет, что глобальный минимум совпадает с заданным TCA.

```text
python tools/build_scenarios.py           # записать scenarios/*.json
python tools/build_scenarios.py --check   # файлы совпадают с генератором?
python tools/build_scenarios.py --report  # таблица ниже
```

## Обоснование статусов

Фактический вывод `python tools/build_scenarios.py --report`:

| Сценарий | Эпоха (UTC), горизонт | TCA | Дистанция | v_rel | Прочие минимумы |
|---|---|---|---|---|---|
| safe_flyby | 2026-12-01 00:00, 4 ч | 12 600 с, широта 6.9° | 4000.000 м | 14.09 км/с | ≥ 76 км |
| dangerous_feasible | 2026-12-01 00:00, 4 ч | 10 800 с, широта 40.0° | 120.000 м | 13.02 км/с | ≥ 35 км |
| late_warning_no_solution | 2026-12-01 02:45, 45 мин | 900 с, тот же момент | 120.000 м | 13.02 км/с | границы горизонта |

**already_safe.** На всём горизонте минимум 4000 м ≥ 1000 + 1 м. Остальные
минимумы — от 76 км.

**feasible.** Без манёвра 120 м < 1001 м. Пример допустимого импульса
сохранён в `expected.witness_impulse`: +0.1 м/с вдоль орбиты (ось T в RTN)
в t = 0 даёт минимум 1900.4 м на всём горизонте. Это пример существования
решения, а не минимальный Δv. Для ориентира — наименьший |Δv| вдоль ±T в
трёх моментах, с проверкой на всём горизонте:

| Момент импульса | До TCA | +T, м/с | −T, м/с |
|---|---|---|---|
| 0 с | 180 мин | 0.0497 | 0.0623 |
| 5400 с | 90 мин | 0.0993 | 0.1245 |
| 9000 с | 30 мин | 0.3501 | 0.3571 |

Чем раньше манёвр, тем он дешевле. Это согласуется с оценкой
«1 см/с вдоль орбиты ≈ 1 км смещения за сутки».
Это справочные значения для одного направления, не доказанный оптимум.

**no_feasible_candidate.** Сближение то же, спутник и dv_max те же, но
предупреждение пришло за 15 мин, а манёвр возможен только в первые 5 мин.
Для любого импульса с |Δv| ≤ 0.5 м/с в окне [0, 300] с смещение спутника в
исходный момент TCA равно δr = Φ_rv(t_TCA, t_b)·Δv + O(Δv²). Отсюда:

- max по направлениям = σ_max(Φ_rv) = 1213.0 с (при t_b = 0). Значение
  совпадает с линейной теорией Клохесси — Уилтшира в пределах 1% (тест);
- перебор t_b с шагом 1 с плюс наибольший скачок σ между узлами: 2.04 с;
- нелинейная часть 9·10⁻³ м, учтена с двукратным запасом.

Граница — 608 м (в файле `shift_bound_m`). Дистанция в исходный момент
TCA ≤ 120 + 608 = 728 м < 1001 м. Минимум на горизонте не больше дистанции
в этот момент, поэтому безопасного манёвра в заданных пределах нет —
**для любой сетки кандидатов** OG-04, не только для проверенной. Вывод
относится к модели и пределам сценария, а не к невозможности уклонения
вообще.

## Проверка независимым численным расчётом

Файлы прогнаны через `propagate` (OG-02, PR #17) и `find_closest_approach`
(OG-03, PR #21) с численными параметрами сценария:

| Сценарий | t численно | Δt | d численно | Δd | (v·Δt)²/2d |
|---|---|---|---|---|---|
| safe_flyby | 12600.000305 с | +3.05·10⁻⁴ с | 4000.0023 м | +0.0023 м | 0.0023 м |
| dangerous_feasible | 10800.000305 с | +3.05·10⁻⁴ с | 120.0658 м | +0.0658 м | 0.0658 м |
| late_warning_no_solution | 899.999695 с | −3.05·10⁻⁴ с | 120.0658 м | +0.0658 м | 0.0658 м |
| dangerous_feasible + пример манёвра | 10800.221 с | — | 1900.3623 м | +0.0004 м | — |

Отличие дистанции целиком объясняется квадратичным минимумом. Поиск OG-03
останавливается при ошибке момента < `closest_time_tol_s` (1 мс), а при
13 км/с это даёт 4 м вдоль относительной скорости. Поэтому в `expected.tolerance`
допуски такие: момент 0.01 с (критерий contracts.md), дистанция 1 м.
Оценка (v·δt)²/(2d) < 0.2 м при δt ≤ 0.5 мс, d ≥ 100 м, v ≤ 15 км/с —
остальное запас. Допуски выбраны до сравнения, а не подогнаны под него.

## Формат файла

JSON schema_version 1 из contracts.md: все поля `Scenario` явно, СИ,
ECI-J2000, эпоха с суффиксом `Z`. Векторы записаны кратчайшим точным
представлением float64, поэтому загрузка повторяет значения бит в бит.

Необязательный блок `expected` (не влияет на расчёт):

| Поле | Содержание |
|---|---|
| `status` | Ожидаемый статус `search_maneuver` |
| `closest_approach` | `t_s`, `distance_m`, `rel_speed_mps` без манёвра — по построению |
| `tolerance` | `t_s`, `distance_m` для сравнения с численным расчётом |
| `basis` | Обоснование статуса текстом |
| `witness_impulse` | Только для `feasible`: `t_s`, `dv_eci_mps`, `min_distance_m` |
| `shift_bound_m` | Только для `no_feasible_candidate`: граница смещения, м |

Загрузчик строгий. `ValueError` с именем файла и поля вызывают:
- неизвестные или пропущенные поля, повторные ключи;
- NaN, Infinity, переполнение;
- строки или булевы значения вместо чисел;
- неверные версия, система координат, эпоха не в UTC;
- нарушения проверок `models` (горизонт, окно, порог);
- противоречивый блок `expected`. Например, `already_safe` при дистанции
  меньше порога с запасом, пример вне окна или с Δv > dv_max, граница,
  которая не доказывает отсутствие решения.

API (`src/orbitguard/scenarios.py`):

```python
load_scenario(path) -> Scenario                  # контракт OG-01
load_scenario_file(path) -> (Scenario, Expectation | None)
load_expectation(path) -> Expectation | None
save_scenario(scenario, path, expected=None)     # обратное к загрузке
scenario_paths(directory=SCENARIO_DIR) -> list[Path]
```

## Ограничения

- **Только центральное поле.** Сценарии построены и проверены в той же
  модели, что и расчёт. С J2 узел орбиты спутника за 3 ч смещается на
  0.62° (−4.9° в сутки), а аргумент широты — ещё на ~0.5°. Каждое из этих
  смещений даёт десятки километров в точке встречи, и сближение пропадёт.
  После OG-13…15 сценарии нужно перестроить с выбранной моделью сил:
  заменить аналитический перенос численным той же моделью.
- **Атмосферный сценарий из BACKLOG OG-06 отложен до OG-14.** Сейчас
  `propagate` на `drag=true` поднимает `UnsupportedForceError`. Масса,
  площадь и Cd в файлах уже заданы, чтобы сценарии можно было переиспользовать.
- **Порог 1 км — детерминированная дистанция, не вероятность столкновения.**
  Операторы решают по вероятности: по рекомендации NASA CARA меры
  принимаются при Pc > 1e-4. Зоны отбора CARA для LEO — порядка ±1–2 км по
  радиусу и десятков км вдоль и поперёк орбиты. Неопределённость
  орбит в модели не учитывается.
- **Импульсный манёвр.** Двигатель работает конечное время. Для 0.1 м/с
  при 40 мН и 10 кг это ~25 с — допустимо, но не ноль.
- **Расход топлива.** Масса спутника в сценарии есть, а удельного импульса
  в контракте нет. Без Isp показываем только Δv (AGENTS.md). Поле Isp нужно
  согласовать в #1 для OG-05.
- **Элементы орбиты на входе.** DEV_GUIDE §6 предлагал задавать объекты
  элементами. Контракт v0.1 принимает только `state0`, поэтому элементы есть
  в генераторе и в этом документе, а не в JSON.
