# OG-02: двухтельный расчёт и подключение OG-03

Реализован `orbitguard.propagation.propagate`, также доступный через
`orbitguard.api.propagate`. Контракт — [contracts.md](contracts.md).
Это численный прогноз в упрощённой модели, не гарантия безопасности миссии.

## Что получает разработчик поиска сближений

```python
from datetime import datetime, timezone
from orbitguard.models import ForceModel, SpaceObject
from orbitguard.propagation import propagate

epoch = datetime(2026, 11, 22, tzinfo=timezone.utc)
satellite = SpaceObject("satellite", [7000000, 0, 0, 0, 7546, 0])
debris = SpaceObject("debris", [7000000, 1000, 0, 0, 7546, 0])
a = propagate(satellite, epoch, (0, 600), ForceModel())
b = propagate(debris, epoch, (0, 600), ForceModel())

# Одинаковое время, даже если адаптивные шаги интегратора различались.
relative_position_m = a.state_at(123.456)[:3] - b.state_at(123.456)[:3]
relative_velocity_mps = a.state_at(123.456)[3:] - b.state_at(123.456)[3:]
```

`state_at` принимает скаляр, возвращает копию `(6,)`, не экстраполирует.
`t_s` — упорядоченная выходная сетка, `states` — `(N,6)`, обе read-only.
Без импульсов одинаковые горизонт и max_step_s дают одинаковую сетку вывода.
При импульсе его время добавляется в сетку, поэтому для сравнения объектов
нужно использовать общий набор времён и state_at, а не номера строк.
`epoch` и `frame` доступны для проверки совместимости.

На импульсе `state_at(t, side="left")` возвращает состояние до изменения скорости,
`side="right"` — после. В states хранится правое состояние. Это касается также
импульсов ровно в начале или конце горизонта. Между сегментами нет интерполяции
через скачок скорости; каждая часть имеет собственное dense output RK45.

Для OG-03: исследовать границы, локальные минимумы и времена импульсов;
относительная скорость — производная относительного положения. Нуль их
скалярного произведения означает стационарную точку квадрата расстояния,
но ещё не гарантирует минимум. Не выбирать только минимум табличных строк.

## Модель и ошибки

- `dr/dt=v`, `dv/dt=−μr/|r|³`, μ и сферический радиус — constants.py.
- RK45 с dense output, покомпонентным atol и max_step_s из Numerics.
- Вектор Δv добавляется к скорости; исходный SpaceObject не изменяется.
- J2/атмосфера/Луна/Солнце пока вызывают UnsupportedForceError. Их включение
  должно сопровождаться отдельной реализацией и тестами.
- Неверный интервал, эпоха или импульс — ValueError. Поддержан только [0,T], T>0.
- Сбой интегратора и снижение к границе 100 км — PropagationError;
  незавершённая траектория не возвращается как успешная.
- Событие границы ищет пересечение между шагами RK45. При пользовательском
  чрезмерно большом max_step_s несколько пересечений за шаг могут быть пропущены;
  стандартный шаг 10 с и тест сходимости — базовая настройка для LEO,
  не доказательство корректности для любых экзотических входов.

Метод, dense output, вектор atol и особенности событий:
[официальная документация scipy.integrate.solve_ivp](https://docs.scipy.org/doc/scipy/reference/generated/scipy.integrate.solve_ivp.html).
