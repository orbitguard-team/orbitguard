# Контракт OrbitGuard v0.1 — OG-01

Кандидат на общий API, согласованный с постановкой #1 и предложением Анны в обсуждении.
Становится принятой базой после независимого review и merge PR; создание этого файла
само по себе не означает завершение OG-01. Изменения API обсуждаем в issue и фиксируем здесь.

## Граница этапа

В #1 входят типы, проверка входа, сигнатуры, численные критерии и пример данных.
Численные алгоритмы ещё не реализованы: `orbitguard.api` поднимает `NotImplementedError`.
Это не результат физического расчёта. Реализации размещаются в `propagation.py` (#2),
`conjunction.py` (#3), `maneuver.py` (#4), `scenarios.py` (#6);
`api.py` затем реэкспортирует их с неизменными сигнатурами. CI остаётся #9.

**Обновление OG-02:** `propagate` теперь реализован и реэкспортируется из api.py.
Описание и фактические проверки — [propagation.md](propagation.md).
Остальные алгоритмы по-прежнему явно NotImplementedError.

Базовый режим: сферическая Земля, центральная гравитация, два невзаимодействующих
точечных объекта, один импульс спутника. Расширения J2/атмосфера/Луна/Солнце
предусмотрены в `ForceModel`, по умолчанию выключены. Запрос ещё неподдерживаемой силы
обязан вызвать `UnsupportedForceError`, а не незаметно изменить модель.
Это уточняет этапность PLAN.md: расширения остаются в плане, но не блокируют проверку базы.

## Координаты, время, размерности

- Все внутренние величины SI: м, с, м/с, кг, м²; углы — радианы.
- `frame="ECI-J2000"`: геоцентрическая правая система; x направлена к среднему
  равноденствию J2000, z — к среднему северному полюсу J2000, y дополняет тройку.
  Для базовой модели ориентация постоянна. В расширениях ось Земли приближённо
  совпадает с z; это явно упрощённая модель, не высокоточная трансформация ITRF/GCRS.
- `epoch` — timezone-aware UTC datetime. `t_s=0` соответствует epoch.
  Относительное время — непрерывные SI секунды. Сценарии не пересекают вставку секунды
  координации; отдельного преобразования UTC/TT пока нет. Эфемериды OG-15 должны
  документировать шкалу времени и преобразование до включения силы.
- `SpaceObject.state0`: float64 `(6,)` = `[x,y,z,vx,vy,vz]` в epoch.
  Позиция — от центра Земли, **не высота над поверхностью**.
- `Trajectory.t_s`: `(N,)`, N >= 2, конечная строго возрастающая сетка,
  содержащая обе границы расчёта; `states`: `(N,6)` в тех же единицах.
  `epoch` и `frame` хранятся в каждой траектории и должны совпадать при сравнении.
- `state_at(t_s, side="right") -> (6,)`: скалярное время, без экстраполяции.
  Вне области и неизвестный side — `ValueError`. На импульсе left/right возвращают
  пределы до/после: позиция совпадает, скорость отличается на Δv.
  В табличных states хранится правая граница; dense output кусочный, нельзя
  интерполировать скорость через скачок. Для графиков допустима отдельная выборка.
- Frozen dataclasses запрещают переназначение полей; входные массивы копируются
  и помечаются read-only. Это защита от случайной мутации, не граница безопасности.

## Типы

Источник сигнатур типов — `src/orbitguard/models.py`.

| Тип | Содержание и ограничения |
|---|---|
| SpaceObject | Имя, state0; необязательные положительные mass_kg, area_m2, cd |
| ForceModel | Boolean j2/drag/moon/sun, неотрицательный density_scale |
| ForceContext / Acceleration | epoch, объект, конфигурация сил, frame / интерфейс ускорения |
| Numerics | Параметры интеграции, уточнения минимума и запаса расстояния |
| ManeuverLimits | 0 ≤ t_earliest_s ≤ t_latest_s ≤ horizon_s; dv_max_mps ≥ 0 |
| Scenario | Два объекта, epoch, frame, положительные horizon_s/safe_distance_m, limits, forces, numerics, synthetic, source |
| Impulse | t_s ≥ 0, конечный dv_eci_mps `(3,)`; dv_mps — евклидова норма |
| Approach | Неотрицательные t_s, distance_m, rel_speed_mps |
| ConjunctionResult | closest, all_minima, safe_distance_m; violated вычисляется как d_min < порога |
| CandidateResult | Импульс, admissible, after либо None при сбое, reason |
| ManeuverResult | status, best, before, after, полный журнал candidates, message |

Некорректные входы — `ValueError`, ошибки интеграции/выход из допустимой физической
области — `PropagationError`. Граничное расстояние ровно в пороге не violated,
но для принятия манёвра дополнительно нужен запас, описанный ниже.
Если drag=True, все три физических параметра обязательны для обоих объектов;
их отсутствие — ошибка ввода. Это уточнение PHYSICS.md: сила не пропускается молча.

## Сигнатуры и поведение

```python
propagate(obj, epoch, t_span_s, forces, *, numerics=Numerics(), impulses=()) -> Trajectory
find_closest_approach(a, b, safe_distance_m, t_span_s, *, numerics=Numerics()) -> ConjunctionResult
search_maneuver(scenario, *, candidates) -> ManeuverResult
load_scenario(path) -> Scenario
```

`propagate`: t_span_s=(0,T), T > 0; state0 всегда относится к epoch, не к началу
произвольного подотрезка. Внутренний интегратор может разбивать интервал.
В MVP допустимы ноль или один импульс, 0 ≤ t_impulse ≤ T; выход за пределы — ValueError.
Импульс в 0 применяется перед движением, в T меняет только конечную скорость.
Базовая модель использует μ=3.986004418e14 м³/с² и R=6378137 м.
При r < R+100000 м расчёт прекращается с PropagationError; падение ниже границы
проверяется событием интегратора, не только по выходной сетке. Равенство допустимо.
Начальное состояние проверяется сейчас, пересечение границы — задача #2.
Для атмосферы OG-14 определит эллипсоид и высоту отдельным согласованным расширением.

Подключаемая сила имеет сигнатуру `accel(t_s, r_m, v_mps, ctx) -> (3,)` (м/с²),
где `ctx: ForceContext` содержит epoch, obj, forces и frame.
Векторы r_m/v_mps имеют форму `(3,)`; время — секунды от ctx.epoch.
Функция не меняет входы; центральное ускорение учитывается ровно один раз,
остальные функции возвращают только своё возмущение. Сборка и проверка
поддерживаемых сил — ответственность #2; реализации возмущений — OG-13…15.

`find_closest_approach`: 0 ≤ start < end; обе траектории обязаны покрывать весь
запрошенный интервал. Несовпадение epoch/frame или нехватка покрытия — ValueError,
без автоматического обрезания горизонта. Сравниваем позиции в один и тот же момент.
Возвращаем минимум по проверенным границам и уточнённым локальным минимумам;
all_minima включает границы, отсортирован по времени, без повторных времён.
При равном расстоянии выбирается самое раннее время.
Корни (r_a-r_b)·(v_a-v_b)=0 — кандидаты стационарных точек, не все они минимумы.
Нужно также проверить границы, изломы в моменты импульсов, постоянное расстояние,
несколько минимумов и чувствительность к сетке. Шаг 10 с не доказывает,
что все экстремумы найдены. Проверка с уплотнением обязательна в #3.

`search_maneuver`: candidates — конечная упорядоченная последовательность импульсов
в ECI. Так параметры поиска можно сохранить и воспроизвести без скрытой сетки.
Кандидаты вне окна или dv_max не интегрируются и записываются с admissible=False
и причиной. Каждый оставшийся проверяется на **всём** [0,horizon_s], включая участок
до импульса. Ошибка отдельного кандидата не прерывает перебор, записывается reason.
Выбор: минимальная норма Δv, затем время, затем исходный индекс кандидата.
Пустая последовательность при опасном исходном движении → no_feasible_candidate.
Деление пополам по величине Δv не используется без доказанной монотонности.

RTN для генерации сетки (#4): R=r/|r|, N=(r×v)/|r×v|, T=N×R, состояние берётся
**до** импульса. Δv_ECI = [R T N] Δv_RTN. Нулевой r×v — явная ошибка.
RTN можно выводить в UI, но единственный источник истины в Impulse — ECI,
чтобы два сохранённых вектора не противоречили друг другу.

| status | best | before / after |
|---|---|---|
| already_safe | None; расход Δv=0 | Одинаковый исходный результат, уже с запасом |
| feasible | Выбранный Impulse | Исходный и пересчитанный результаты |
| no_feasible_candidate | None | before есть, after=None; среди проверенных нет допустимого |
| propagation_failed | None | before/after могут отсутствовать; исходный прогноз не получен |

no_feasible_candidate не доказывает невозможность других манёвров.
propagation_failed не означает безопасную траекторию. Ошибки конфигурации не
маскируются этими статусами. Перебор ловит только ожидаемые PropagationError;
NotImplementedError и ошибки программы должны оставаться видимыми.

## Численная точность и приёмка алгоритмов

Стартовые параметры, зафиксированные **до** реализации:
rtol=1e-10, atol положения=1e-3 м, скорости=1e-6 м/с,
closest_time_tol_s=1e-3 с, max_step_s=10 с, distance_margin_m=1 м.
Для solve_ivp atol имеет форму `(6,)`: три допуска положения, три скорости.
Это локальные допуски интегратора, не гарантия глобальной ошибки в 1 мм.

Кандидат допустим, если траектория в физической области, ограничения выполнены
и d_min ≥ safe_distance_m + distance_margin_m. Исходный already_safe использует
тот же критерий. Полоса в 1 м — консервативный запас, не вероятностная оценка.
При интеграционной валидации повторный расчёт с rtol/atol/10 и max_step/2
должен менять d_min не более чем на 0.1 м, t_min не более чем на 0.01 с
для изолированного минимума. При плоском/равном минимуме проверяется расстояние,
а не уникальность времени. Несходимость — основание отвергнуть подтверждение,
а не расширить допуск под получившуюся ошибку.

Эталон #2: круговая орбита радиуса 7000000 м, скорость sqrt(μ/r), один период
2π sqrt(r³/μ), только центральное поле. Ошибка возвращения положения ≤1 м,
скорости ≤0.001 м/с; максимальный относительный дрейф удельной энергии
v²/2−μ/r и момента |r×v| ≤1e-8. Проверить более строгий повторный расчёт.
Эти проверки ещё **не выполнены** в #1: здесь нет интегратора.
Энергия двухтельной модели не является инвариантом при включённых произвольных силах.

## JSON и пример для разработки

`examples/scenario.json` — schema_version=1. Все поля Scenario сохраняются явно;
epoch в ISO 8601 с Z/UTC, массивы как JSON lists, ForceModel/Numerics/Limits как objects.
Загрузчик #6 отклоняет неизвестную версию, неизвестные поля, NaN/Infinity, неверные
единицы/систему и передаёт значения через валидируемые dataclasses.
Числа примера — синтетические **начальные условия**, не прогноз сближения.
Ожидаемый статус безопасности не заявлен; UI не должен рисовать результат расчёта
на основании этого файла. `examples/contract_example.py` создаёт тот же Scenario
без загрузчика и подходит для разработки UI/валидации.

## Установка и проверки

Python 3.11–3.13 (рекомендуется 3.13), виртуальное окружение:

```text
python -m venv .venv
# Windows: .venv\Scripts\Activate.ps1
# Linux/macOS: source .venv/bin/activate
python -m pip install -e ".[dev]"
python -m pytest -q
python examples/contract_example.py
# Для UI позднее: python -m pip install -e ".[dev,ui]"
```

Границы версий заданы в pyproject.toml. Точные версии проверенного окружения
фиксируются в PR; это пока не lockfile для всех платформ. Финальная
воспроизводимость расчётов и экспорт среды относятся к #5/#10.
