# Первый запуск участника и его агента

Общий репозиторий: https://github.com/orbitguard-team/orbitguard
Доска: https://github.com/orgs/orbitguard-team/projects/1/views/1
Стартовые документы: ветка `codex/docs`.

## Участнику

1. Прими приглашение в организацию/репозиторий. Проверь, что видишь закрытый репозиторий.
2. Используй свой GitHub-аккаунт, включая подключение агента. Общий токен не нужен.
3. Открой локальную копию репозитория в агенте. Если копии нет, попроси его клонировать:

```sh
git clone --branch codex/docs https://github.com/orbitguard-team/orbitguard.git
```

4. Передай агенту промпт ниже. Для начала достаточно проверки доступа и чтения документов.
5. После назначения реального issue поручай его выполнение отдельным сообщением.

## Промпт первичного подключения

```text
Работаем в https://github.com/orbitguard-team/orbitguard.
Стартовые документы находятся в ветке codex/docs.
Если локальной копии ещё нет, клонируй эту ветку в отдельную папку.
Если копия уже есть, сначала проверь git status и remote, не затирай локальную работу.

Прочитай START_HERE.md, AGENTS.md, README.md, docs/PLAN.md и docs/BACKLOG.md.
Проверь GitHub-аккаунт и доступ к репозиторию, issues, PR и Project:
https://github.com/orgs/orbitguard-team/projects/1/views/1

Пока не меняй код и не создавай задачи. Сообщи, какие доступы готовы,
каких не хватает, и кратко перескажи правила работы.
OG-xx в backlog — обозначения плана, а не реальные номера GitHub issues.
```

## До начала разработки

Интегратор создаёт main на основе проверенной ветки codex/docs и назначает main веткой по умолчанию.
Пока main отсутствует, не открывайте PR с кодом в codex/docs и не начинайте независимые истории Git.
После появления main новые рабочие ветки создаются от актуальной main.
Документы должны попасть в main, чтобы все агенты получали AGENTS.md при обычном клонировании.

Затем публикуются issues из docs/BACKLOG.md, каждому назначается один исполнитель.
Сначала согласуется OG-01 (архитектура/API), затем можно вести несколько задач параллельно.
Не публикуйте дубли issues от каждого участника: это делает один координатор.

## Промпт на выполнение

```text
В orbitguard-team/orbitguard выполни issue #N по AGENTS.md.
Проверь обсуждение, зависимости и assignee. Если задача занята другим участником, не дублируй её.
Работай в отдельной ветке от актуальной main, отметь In process.
Разрешаю публиковать относящиеся к задаче комментарии и PR в этом репозитории.
Проверь критерии приёмки, открой PR с Closes #N, запроси review у @LOGIN
и отметь In review. Не делай merge. Верни ссылку на PR и результаты проверок.
```

## Промпт на ревью чужого PR

```text
В orbitguard-team/orbitguard сделай ревью PR #N по AGENTS.md.
Проверь связанный issue, актуальный diff и релевантные тесты.
Разрешаю опубликовать review и замечания в этом PR.
При существенных ошибках используй Request changes; если всё готово — Approve
с описанием проверок. Не одобряй PR моего аккаунта. Не делай merge.
```

## Общение

Вопросы и решения по задаче — в issue. Замечания к изменениям — в PR.
Один независимый Approve, успешные настроенные проверки и выполненные критерии позволяют интегратору сделать merge.
Комментарий GitHub не запускает агента коллеги: коллега должен поручить ему прочитать обновления.
